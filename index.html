How it works

  1. 01

    Show your bookmarks bar

    ⌘ + Shift + B on a Mac, Ctrl + Shift + B elsewhere.

  2. 02

    Drag the tool's button onto it

    Each tool has a button named after it. Drag the button, not the card, and the bookmark arrives named — emoji included. No renaming afterwards.

  3. 03

    Pick a set, export a folder

    Tick tools, download bookmarks.html, then import it in your browser's bookmark manager.

Bookmarklets run with the permissions of the page you click them on. Clipboard, camera and screen-capture tools ask the browser first. If dragging is blocked, use Copy and paste the code into a new bookmark's URL field.

Questions

What is a bookmarklet?

A bookmark whose address is a short piece of JavaScript instead of a web address. Click it on a page and it runs there, without installing an extension.

How do I install a bookmarklet?

Show your bookmarks bar with ⌘ + Shift + B on a Mac or Ctrl + Shift + B elsewhere, then drag a tool's named button onto the bar. The bookmark arrives already named, emoji and all.

Do bookmarklets need an extension or an account?

No. Every tool is one bookmark, and the whole catalog is static HTML, CSS and JavaScript. There is no sign-in and no tracking. Two tools use a hosted helper: URL chat loads PeerJS from a CDN because WebRTC needs a signalling broker, and Doom loads a WebAssembly engine and the shareware WAD from this site.

Does Doom need a WAD or an install?

No. The bookmarklet opens a hosted page that loads the shareware DOOM1.WAD and a WebAssembly engine in a centered window, about 7 MB on the first visit. It starts on E1M1 behind a Click to play gate; Play enables sound and asks for pointer lock. Expand fills the browser, or use Open in tab if the page blocks embedded frames. Esc pauses and releases the mouse; Close exits. Free-look is on, so the mouse tilts the view as well as turning it; aiming still uses Doom's autoaim. It needs WebAssembly and network access.

Are bookmarklets safe to use?

A bookmarklet runs with the permissions of the page you click it on, so treat it like a snippet you paste into the console. Every tool here is a readable source file linked from its page, and clipboard, camera and screen tools ask the browser before doing anything.

Are all of these tools yours?

No. Most are built here, and some are kept from other developers. Those cards name the original author and link to the source, and the full page also links the readable file in this repository. The author's name is kept, with an emoji added for the bookmarks bar.

Do the meeting, chat and voice tools need an account?

No. Jitsi opens a room on the public meet.jit.si service, and URL chat uses PeerJS over WebRTC through a hosted page; there is no sign-in and no server of ours. The chat room name comes from the page URL, so anyone who can derive that URL can join. Voice commands need microphone permission and a browser with SpeechRecognition, which today means Chrome or Edge.

What happens to the page when I use the PII, form or webhook tools?

Nothing leaves the page unless you press Send in the webhook tool. The PII masker edits text in place and can restore it; the form harvester writes JSON to localStorage under bl:form, and the stamper fills fields from it; the environment switcher stores origins under bl:envs; the webhook stores the endpoint under bl:webhook. Password and file fields are skipped by the form pair, and a reload discards the mask.

Do the ZIP tools work in every browser?

Zipping works in current Chrome, Edge, Firefox and Safari. Unzipping shows the archive and downloads individual files anywhere; saving the whole folder in one step needs the File System Access API, which only Chrome and Edge provide. Both tools use standard ZIP32: no password-protected archives, no ZIP64 and no split archives, and nothing is uploaded.

Do the Office conversion tools need Office?

No. They run in the browser and read .docx, .docm, .odt, .xlsx, .xlsm, .ods, .html, .rtf, .txt, .md, .csv and .tsv; they write .html, .txt, .rtf, .pdf, .md, .docx, .odt, .xlsx and .ods. One result downloads directly; two or more offer Save all to folder in Chrome or Edge, or Download ZIP. PDF output uses Helvetica and Latin-1, so unsupported characters are replaced, and headers, footers, comments and tracked changes are not carried. Password-protected and ZIP64 OpenDocument files are refused, as are legacy .doc and .xls files. Nothing is uploaded.
